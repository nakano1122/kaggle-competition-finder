# Web フロントエンドデザイン

React 実装を伴うため、最初に同階層の `vite-react-frontend-developer/SKILL.md` も読む。対象画面、既存のデザイントークン、導入済みの shadcn/ui コンポーネントを確認し、追加ライブラリより既存部品を優先する。

- 画面は外側から決める。ページ幅、余白、主要領域、カード、内部要素の順にレイアウトし、子要素の固定位置で親の配置を補正しない。
- 実績入力、クエリ編集、検索実行、検索結果、お気に入りを視覚的に区切る。検索パイプラインの現在段階、モデルのロード、処理中、エラー、空状態を見落としにくくする。
- コンペ結果はタイトル、期限など API から得た事実、関連度、要約、推薦理由を区別して表示する。説明にない内容を公式情報のように見せない。
- 余白、文字サイズ、色、状態表現を一貫させる。コントラスト、キーボード操作、ラベル、フォーカス表示を保ち、アイコンだけで重要な操作を表現しない。
- Tailwind の任意値や独自 CSS は既存のトークンとコンポーネントで表現できない場合に限定する。見た目のためだけの wrapper、無意味なコンポーネント分割、固定高さを避ける。

実装後は狭い画面と広い画面で確認し、キーボード操作と検索結果の各状態を確認する。デザイン変更がコードを伴う場合は対象フロントエンド package の検証も実行する。
