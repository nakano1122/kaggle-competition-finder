# プロジェクト用 Skill 作成

作成前に、対象の作業、既存 skill、`AGENTS.md`、関連する仕様と package 構成を確認する。一般的な開発常識を複製せず、このリポジトリで判断を変える制約だけを記録する。

- `name` は小文字・数字・ハイフンで短くし、フォルダ名と一致させる。`description` には対象作業と誤って適用しない境界を書く。
- `SKILL.md` は目的、非自明な制約、必要な確認・検証に絞る。詳細な手順、スキーマ、繰り返し実行する操作だけは必要に応じて `references/` または `scripts/` に分ける。
- 既存の skill と役割が重なる場合は、より狭い作業境界にして相互参照を最小限にする。未使用の assets、サンプル、README、空ディレクトリを追加しない。
- API、ライブラリ、Cloudflare のように更新される外部仕様は、固定値を skill に写さず、実装時に公式情報と導入済みバージョンを確認するように書く。
- 作成・変更後は `quick_validate.py` で各 skill を検証し、説明文、参照先、対象外の境界が実際に判断できる内容か見直す。
